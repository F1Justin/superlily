## 回滚

仅回滚 claim 行为：将生产 `.env` 中
`SUPERLILY_CLAIM_OBSERVE_ONLY_OUTSIDE_CANARY=false`，然后仅重建 Core：

```bash
sudo docker compose --env-file .env -f deploy/compose.yml up -d --no-deps --no-build --timeout 60 lily-core
```

若需回滚镜像，先保留之后新增的配置，再执行：

```bash
sudo docker image tag superlily/core:pre-ablation-20260912 deploy-lily-core
sudo docker compose --env-file .env -f deploy/compose.yml up -d --no-deps --no-build --timeout 60 lily-core
```

恢复 Wolfram Provider 执行轮询：将 `.env` 的 `SUPERLILY_WOLFRAM_PROVIDER_MODE=serve`，
只重建 `wolfram-provider`，使用相同的 `--no-deps --no-build` 参数。
两个闲置 Provider 的旧容器仍可 `docker start`，profile 配置也可独立恢复。
以上操作都不修复 Wolfram 内核故障，不应使用 9 月 8 日旧 Core 镜像回滚本次变更。
