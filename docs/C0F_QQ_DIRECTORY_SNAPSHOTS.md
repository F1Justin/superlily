# R5.2（C0-F）QQ 通讯录与群成员快照

状态：实现完成，待生产验收（2026-09-04）。

## 用户结果

即使某个 QQ 号从未发言，Superlily 也应能从定期平台快照中查到它当时所在的群、QQ 昵称、
群名片、成员身份和群头衔；好友昵称、备注、分类，以及群名称、群备注和人数状态也应按采集
时间留存。快照与消息事件共同进入既有名称历史，使按 QQ 号查询不再局限于发过言的人。

## 采集范围

桥接器使用已在 NapCat 4.8.110 部署包中核实的接口：

- `get_group_member_list`：QQ 号、昵称、群名片、角色、头衔、成员等级、QQ 等级、入群时间、
  最后发言时间、禁言截止和机器人标记；
- `get_group_info_ex`，并以 `get_group_list` 提供范围和降级资料：群名称、群备注、成员数、容量
  和全员禁言状态；
- `get_friends_with_category`，失败时降级到 `get_friend_list`：好友 QQ 号、昵称、备注和分类。

每个群形成一份有界成员快照，好友形成一份通讯录快照。Core 保存快照头和可按 QQ 号索引的
成员/好友明细，并把成员昵称、群名片、好友昵称和群名称投影到现有名称观测表。完全相同的
状态在不同采集时间仍是不同快照；同一 `snapshot_id` 重投则幂等。

## 隐私、失败和运行边界

- NapCat 好友结果中的手机号、邮箱、生日、年龄和性别不采集；未知字段也不透传。
- 单个扩展接口失败时保存 `partial` 和接口异常类型，不把空成员列表伪装成完整快照。
- 每个目录 API 调用默认最多等待 30 秒；超时按接口失败处理，避免一个 NapCat 请求永久阻塞
  整轮每日快照。
- NapCat 刚连接时若群列表暂为空，不把空结果视为当天采集完成，而是在 60 秒后重试。
- 采集默认关闭，建议显式启用后以 24 小时为周期；它不会在本次代码提交中自动改变生产负载。
- 快照上报走有重试的后台队列。它是可重复的周期性观察，不进入消息事件的持久 spool；一次
  失败由下一周期重新读取平台状态弥补，不能声称恢复失败期间的历史状态。
- 不回填 NapCat 从未提供过的过去状态，不修改 ChatExporter，不自动调用任何有副作用接口。

## 验收门与回滚

1. 两套桥接器产生逐字节一致的规范化逻辑，合同拒绝混合类型和额外隐私字段。
2. Core 能幂等保存完整与部分快照，可按 QQ 号索引成员/好友记录，并产生名称历史。
3. SQLite 迁移 upgrade/downgrade/upgrade 和全量可运行回归通过。
4. 生产发布需另行启用开关，先单实例观察 API 耗时、后台队列、错误日志和数据库增长，再决定
   是否启用另一实例。

回滚时先关闭快照开关并恢复上一桥接器版本；如需回退 schema，再 downgrade
`0030_qq_directory_snapshots`。已采集快照不因关闭开关自动删除。
